## The problem

A migration that finishes instantly on your laptop can freeze a busy table in production. `CREATE INDEX` without `CONCURRENTLY` blocks every write for the whole build. A column with `DEFAULT gen_random_uuid()` rewrites the table. Coding agents write these all the time, because they're correct SQL.

| Migration on 2M rows | Build time | Writes blocked |
| --- | --- | --- |
| `CREATE INDEX` | 2.48s | **2.48s** |
| `CREATE INDEX CONCURRENTLY` | 2.59s | **33ms** |

</div>

## What it does

<div class="dl-features">
  <div>
    <h3>Catches it</h3>
    <p>16 rules on Postgres's own parser know which lock each statement takes, and print the safe way to make the same change.</p>
  </div>
  <div>
    <h3>Measures it</h3>
    <p><code>rehearse</code> runs the migration on a throwaway Postgres under live probes and reports how long writes and reads were blocked.</p>
  </div>
  <div>
    <h3>Guards your agent</h3>
    <p>A Claude Code plugin checks every migration the agent writes and hands back the fix. Codex, Cursor and a GitHub Action are covered too.</p>
  </div>
  <div>
    <h3>Fits your stack</h3>
    <p>Plain SQL, Prisma, Drizzle, Supabase, Rails, Django and Knex. Text, JSON, GitHub annotations and SARIF output for CI.</p>
  </div>
